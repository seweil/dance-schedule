src/lib

3 findings

Parsing and layout math — the highest correctness risk in the codebase. Held up well; two real bugs found in the schedule-grid algorithms.

Bugsrc/lib/parseDanceScheduleSheet.ts:512
Room-booking conflict check doesn't dedupe rooms the way the caller-booking loop just above it does.
The caller loop explicitly guards with new Set(session.callers). The room loop doesn't. A "ROOMS: Ballroom A, Ballroom A" typo produces a nonsensical self-referential "already booked" build error — or, if that check were skipped, a duplicate rendered card in the grid.
Bugsrc/lib/computeDanceScheduleCallerLayout.ts:241
A "free" floating entry only clips against another entry that starts strictly after it — a same-start neighbor never triggers a clip.
A break card and a real session starting at the identical time: the break renders full-width overlapping the real session for its whole span. An existing test exercises this exact coincident-start case but only asserts lane/columnSpan, not the row span that would catch it.
No testsrc/lib/assignLanes.ts
The shared greedy lane-assignment algorithm used by both dance-schedule layout files has no colocated unit test.
Unlike nearly every other file in the directory. Only exercised indirectly through two much larger consumer suites, so a regression here is easy to misattribute.

src/hooks

5 findings

Comparatively mature and well-tested — most stateful logic is both carefully commented and covered by regression tests that name the bug they prevent.

Bugsrc/hooks/useTextSizePreference.ts:39
Applies the stored text-size preference via a plain useEffect — after first paint, not before.
A returning visitor with a saved "large" or "x-large" preference sees a visible flash to normal size on every page load, then a correction. This repo already fixed this exact class of bug elsewhere with useLayoutEffect — just not here, on the setting most likely to matter to the accessibility-motivated users who set a non-default size.
Bugsrc/hooks/useLastPagePersistence.ts:31
The "is this the initial render" guard is a per-instance ref, not module-level, so StrictMode's dev-only double-invoke defeats it.
On a cold launch with a stored redirect target, the second StrictMode invocation clobbers the just-read value back to / in storage — self-corrects once real navigation fires, so it's dev-only and transient, but confusing to debug locally.
No testsrc/hooks/useDismissableMenu.ts
No colocated test, unlike 14 of the other 16 hooks in this directory.
Owns real interaction logic — Escape-to-close, outside-pointerdown, dual root/portal containment — used by both the desktop nav dropdown and the mobile menu. The easiest kind of logic here to regress silently.
Efficiencysrc/hooks/useFirstLaunchHint.ts:105
getSnapshot passed to useSyncExternalStore is a fresh closure every render instead of stable.
Causes extra defensive re-invocation and localStorage reads on hot-render paths like the dance-schedule filter slider. Not incorrect — the sibling subscribe argument on the line above is already memoized correctly.
Cleanupsrc/hooks/useFirstLaunchHint.ts:25
The module-level subscriber map never removes an id's entry once its set is empty.
Unbounded in principle; low impact today given the small, fixed set of hint ids in use.

8 findings

Bugvite-plugin-content-config.ts:127Verified via repro

Bugcontent-config.ts:69Verified via repro
An empty-string default content-set name isn't rejected, because it resolves to the content directory itself, which always exists.
Would pass validation and fail much later with a confusing raw "file not found" deep in an unrelated plugin, instead of the named error this exact function exists to give.
Bugvite-plugin-content-config.ts:24Verified via repro
Default-value fallbacks also silently mask an explicit-but-blank YAML value, not just a genuinely absent key.
A config key left blank mid-edit (or after a merge conflict) silently takes the default with no error, the same way a wrong-typed value would — except the wrong-typed case one line later does throw.
Bugcontent-config.ts:123
The PWA app name is validated only for being a string, not for being non-empty.
An explicit empty string from a bad template fill-in ships as the blank app name on a real event's installed PWA, with no build error.
Bugcontent-config.ts:40
One code path — config file entirely missing — skips the validation every other path through the same function enforces.
If the fallback default set were ever renamed or deleted, this path alone would surface the failure much later and more confusingly than the named error the other paths give.
Efficiencyvite-plugin-content-sets.ts:89
The same per-set config file is read from disk and parsed up to four times per build.
Wasted I/O and CPU that scales with content-set count, with no correctness benefit — a single shared parse would do.
Duplicationcontent-config.ts:110
The "read file, parse YAML, wrap the error" block is duplicated verbatim four times across two files.
A future change to error format or wrapping has to be made in four places by hand — exactly the kind of edit that's easy to apply to three and miss on the fourth.
Bugvite-plugin-content-config.ts:100
